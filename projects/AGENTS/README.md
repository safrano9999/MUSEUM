# MariaDB Gatekeeper Agent

The MariaDB Gatekeeper Agent provides a safe interface between a human operator and one or more MariaDB databases.

The agent translates natural language instructions into SQL queries and executes them under controlled permissions.

It is designed for infrastructure tasks such as:

- inspecting database schemas
- querying data
- creating databases
- creating tables
- adding columns
- creating indexes
- creating database users
- granting permissions

The agent acts as a database steward rather than a destructive administrator.

---

## Security Model

The agent must NOT use the actual MariaDB root account.

Instead, create a dedicated administrative user with most privileges but without destructive permissions.

This user should NOT have permission to execute:

- `DROP DATABASE`
- `DROP TABLE`
- `DELETE FROM`

This prevents accidental data loss caused by incorrect SQL generated by an AI system.

---

## Recommended Database User

Example:

```sql
CREATE USER 'dbgatekeeper'@'localhost'
IDENTIFIED BY 'strongpassword';
```

Grant safe administrative permissions:

```sql
GRANT
  SELECT,
  INSERT,
  UPDATE,
  CREATE,
  ALTER,
  INDEX,
  CREATE VIEW,
  CREATE USER,
  GRANT OPTION,
  SHOW DATABASES
ON *.* TO 'dbgatekeeper'@'localhost';
```

This allows the agent to:

| Operation         | Allowed |
|-------------------|---------|
| Inspect databases | ✔       |
| Query data        | ✔       |
| Create databases  | ✔       |
| Create tables     | ✔       |
| Add columns       | ✔       |
| Create indexes    | ✔       |
| Create users      | ✔       |

But prevents destructive operations:

| Operation      | Blocked |
|----------------|---------|
| DROP DATABASE  | ❌      |
| DROP TABLE     | ❌      |
| DELETE data    | ❌      |

## Environment Configuration

Database credentials are stored in `.env`.

Example:

```
DB_HOST=localhost
DB_PORT=3306
DB_USER=dbgatekeeper
DB_PASSWORD=your_password_here
```

Credentials must never be printed to logs or chat output.

---

## Logging

All executed queries must be written to:

```
queries.log
```

Format:

```
timestamp | database | SQL query
```

This provides a complete audit trail.

---

## Example Use Cases

Typical requests handled by the agent:

- Show all databases.
- Create database mailmuseum.
- Add column `body` to table `emails`.
- When was the last entry in table `orders`?
- Create user `mailagent` and grant access to `mailmuseum`.

---

## Recommended Model Size

Local models in the 3B–7B range typically perform well for SQL generation when the database schema is available to the agent.

---

## Summary

The MariaDB Gatekeeper Agent provides:

- safe database access
- infrastructure automation
- natural language database interaction
- audit logging
- protection against destructive commands
